Contributing
============

Contributions to the project are welcome, including bug reports,
feature requests, documentation improvements, and code contributions.

Reporting issues
----------------

Before opening a new issue, please check whether a similar issue already
exists. When reporting a bug, please provide:

* a description of the problem,
* steps required to reproduce it,
* the expected and observed behavior,
* your Python version and operating system,
* relevant package versions, and
* the complete error message or traceback, if applicable.

Contributing code
-----------------

To contribute code:

#. Fork the repository.
#. Create a branch for your changes.
#. Implement and test your changes.
#. Update the documentation when necessary.
#. Submit a pull request describing the changes.

Please keep pull requests focused on a single issue or feature where possible.

Code style
----------

Python code should follow PEP 8 conventions.

New code should:

* use clear and descriptive names,
* include docstrings for public classes, methods, and functions,
* remain consistent with the style of the existing codebase,
* include or update tests where appropriate, and
* avoid unrelated changes within the same pull request.

Testing
-------

Please run the project's test suite before submitting a pull request and
ensure that existing tests continue to pass.

Documentation
-------------

Changes that modify user-visible behavior should be accompanied by
corresponding updates to the documentation where appropriate.
